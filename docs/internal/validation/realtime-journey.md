# End-to-end journey over the realtime protocol

- **Question:** Can a client driving Halcyonic through its realtime WebSocket protocol and loopback
  HTTP routes complete the full creation and direction loop (speaking an idea, creating a starter
  project, watching an agent build it, running the host's check, previewing and playing a checked
  build, directing a change by voice, linking multiple projects with Omnorium's catalog, making a
  VR version of an existing non-VR project, and reading Salidium and Seorak intelligence while work
  runs concurrently) without fabricating certainty at any step?
- **Date:** 2026-10-31.
- **Environment:** an Apple M5 Max with macOS 26.7; Node.js 24.15.0; .NET SDK 10.0.401;
  `whisper.cpp` 1.9.4-dev (`ggml-large-v3-turbo-q5_0.bin`); `chrome-headless-shell` 145.0.7632.6;
  Codex 0.118.0 confined by macOS `sandbox-exec` ([ADR 0041](../decisions/0041-codex-runs-confined-to-the-project-it-works-on.md));
  Ollama on `127.0.0.1:11434` serving `muse-glimmer:30b-mlx`; Halcyonic on top of `ad53ad3c`.
- **Method:** two complementary proofs over the real control plane and `RealtimeClient`:
  1. A live rehearsal on a scratch control plane (`127.0.0.1:47810`) with synthetic 16 kHz mono WAV
     clips generated by macOS `say` and `afconvert`, transcribed by `whisper.cpp`, and executed by
     both the synthetic mock runtime and a real confined Codex session on `muse-glimmer:30b-mlx`.
  2. The automated integration suite in `apps/control-plane/src/journey.test.ts`, driving the real
     HTTP and WebSocket server with synthetic runtimes and stand-in Omnorium, Salidium, and Seorak
     servers.
- **Status:** Verified on the Mac over the realtime WebSocket and loopback HTTP routes. Not run on a
  physical headset in this check.

In the companion synthetic rehearsal (`j1a-run`), the execution ran on the unconfined `mock`
runtime (`reads_confined: false`). Even after a passing check and a running preview on
`127.0.0.1:47930`, `project.open_on_mac` was refused with `invalid_state` (`"Not every agent run in
this project was confined, so it is not played here."`).

## Automated realtime journey tests (`apps/control-plane/src/journey.test.ts`)

Three end-to-end tests exercise the realtime protocol and HTTP routes against a live loopback
server:

1. **Full single-project loop, automatic checks, FX1 once, and check staleness:**
   - `POST /api/transcriptions` applies speech tidying (`"Um, make a game where I bonk the moles."`
     becomes `"Make a game where I bonk the moles."`) without journaling any event.
   - `execution.start` acknowledges `accepted` while the runtime start is held open and records
     `command.completed` only after the adapter confirms.
   - When Turn 1 modifies `src/index.ts`, `FileObserver` records `execution.files.observed`, which
     automatically submits an internal `project.check` (`received_via: 'internal'`).
   - When Check 1 fails `tsc`, the next `execution.send_instruction` appends the diagnostic lines
     once (`execution.check_output_given`), and a subsequent instruction before any new check does
     not repeat them. A turn that changes no files does not trigger an automatic check.
   - When Turn 3 fixes `src/index.ts`, automatic Check 2 passes (`files: 'current'`),
     `project.preview.start` serves Check 2's built copy, and `project.open_on_mac` is refused
     because the mock runtime is not confined.
   - When Turn 4 modifies `src/index.ts` again, `ProjectView.check.files` transitions immediately to
     `'changed'` while automatic Check 3 is in flight, both `project.preview.start` and
     `project.open_on_mac` are refused with `/files changed since its last check/`, and completing
     Check 3 stops the old preview with `reason: 'new_check'`.
2. **Play on the Mac admission and lifecycle:**
   - With a confined Codex execution (`confined: true`) and a passing laptop-ready check,
     `project.open_on_mac` is refused before `project.preview.start` (`/Start the preview of the
     latest check first/`), admitted once the preview is running (`project.mac_play.started`), and
     stopped automatically (`reason: 'newer_check'`) when a newer check is recorded.
3. **Multi-project Omnorium catalog linking, VR version creation, and concurrent intelligence:**
   - With multiple projects created over the realtime WebSocket (`existing_folder` and `new_folder`),
     `project.link_catalog` is refused before `GET /api/catalog` has been read (`/No catalog has
     been read yet/`).
   - `GET /api/catalog` reads `FakeOmnorium` over the `omnorium.catalog` 1.0 contract with an
     `omc_` credential, returning `reported` projects and folder-origin suggestions
     (`rule: 'github_origin_full_name'`).
   - `project.link_catalog` and `project.unlink_catalog` emit `project.catalog_linked` and
     `project.catalog_unlinked`, update `projection.catalogLink(projectId)`, and reflect linked
     `local.project_ids` in `GET /api/catalog`.
   - Sending `project.make_vr_version` for an existing non-VR web project creates a sibling project
     from the repository's real `starters/iwsdk-vr` template (including `src/palette.ts`,
     `src/look.ts`, `src/decor.ts`, `src/motion.ts`, `src/play-input.ts`, and
     `public/scenes/main.iwsdk.scene.json`), records `project.made_from` with
     `vrVersionInstruction`, and leaves the original non-VR project folder byte-for-byte untouched.
   - While two workstreams run concurrently across the original web project (`claude-agent`) and the
     VR project (confined `codex`), `GET /api/executions/:id/understanding` and
     `GET /api/executions/:id/evaluation` return `available` Salidium and Seorak reports for the
     observed `claude-agent` session and truthful `unavailable` (`runtime_not_observed`) responses
     for the confined Codex session in Halcyonic's own Codex home, while `GET /api/usage-limits`
     returns the provider limit reading. Completing the VR turn triggers automatic internal check,
     preview, and Mac play.

## What was not verified

- A person speaking into the Quest microphone on the headset (`native-panel-voice.md` covers the
  development-only native dictation boundary).
- Opening a checked preview in Quest Browser on an attached headset via
  `pnpm quest:device -- preview` (`quest-browser-preview.md`).
- A live read against a running Omnorium daemon with an owner-issued credential
  (`omnorium-catalog.md`).
