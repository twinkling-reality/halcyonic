# XR client

How the Halora XR client is structured across its engine-free C# core, Unity OpenXR spatial layer, and native Android surfaces, what is verified in automated suites and Editor renders, and what requires physical headset verification. Architectural decision and alternatives: [ADR 0008](../decisions/0008-engine-independent-csharp-client-core.md).

Every XR surface talks exclusively to the Halora control plane, never directly to an agent runtime or to sibling intelligence services ([SYSTEM.md](SYSTEM.md)). `HalcyonicBootstrap` attaches the session connection, `FocusGuard`, and `DeviceMeasures` at startup without forcing a character stage; `RoomBootstrap`, `SoundBootstrap`, `PairingBootstrap`, and `WorldBootstrap` attach their respective subsystems independently at runtime so scene files carry no hard cross-subsystem references. `Stage.unity` holds the stationary Meta Interaction SDK rig configured by `StageSetup` (hand tracking without duplicate hand meshes, `GazeConecaster` with camera-pose head-gaze emulation, `SeatedHandRay` poses, and locomotion disabled).

### Generated C# contracts

`packages/contracts/src/csharp.ts` generates C# wire bindings from the same TypeBox schemas and definition names as the JSON Schema bundle:

- Objects compile to `sealed` classes where every property carries `[JsonProperty(Required = Required.Always)]` for non-null fields or `Required.AllowNull` for `Nullable(...)` fields, rejecting missing keys on deserialization.
- String literal unions compile to enums with wire strings in `[EnumMember]`.
- Discriminated unions (events, commands, realtime messages, sources, provenance, attention reasons, command results, approval subjects, and understanding or evaluation responses) compile to an abstract base class with one `sealed` class per variant and a generated discriminator converter. Shared properties lift to the base class (for example `EventEnvelope.WorkstreamId`), while distinct unions with matching failure shapes emit distinct classes (`NotFoundUnderstanding`, `NotFoundEvaluation`).
- Timestamps remain ISO-8601 strings (`DateParseHandling.None`, formatted by `HalcyonicJson.FormatTimestamp`), and `$type` metadata is ignored (`MetadataPropertyHandling.Ignore`).
- `HalcyonicJson.Tolerant` ignores unknown object properties so an older client tolerates additive server fields; `HalcyonicJson.Strict` rejects unknown properties in tests and local state readers. Unknown enum values and unknown union discriminators fail in both modes because they alter wire semantics and require a protocol version bump.

### Resource-backed shaders and legacy fallback views

Unity strips unreferenced shaders from IL2CPP player builds. Every custom shader therefore ships through a material asset inside a `Resources` folder (`Halcyonic/Character Body` and `Halcyonic/Soft Shape` under `Assets/Halcyonic/Characters/Resources`; `Halcyonic/Room Glass`, `Halcyonic/Room Halo`, `Halcyonic/Room Band`, `Halcyonic/Room Code`, `Halcyonic/Room Cursor`, `Halcyonic/Room Field`, `Halcyonic/Room Glyph`, `Halcyonic/Room Picture`, `Halcyonic/Kit Glass`, `Halcyonic/Kit Pill`, and `Halcyonic/Glaze Surface` under `Assets/Halcyonic/UI/Resources/HalcyonicUI`; `WorldMix` and `WorldPanorama` under `Assets/Halcyonic/World/Resources/HalcyonicWorld`). `ShadersInBuildTests` fails if shipping code names a `Halcyonic/*` shader not backed by a `Resources` material or `Always Included Shaders`, or loads a missing `Resources` material.

Earlier spatial UI classes (`Glaze`, `GlazeButton`, `MenuFrame`, `MenuFrameView`, `PanelModel`, `PanelFrame`, `WorkspacePanel`, `KitWorkView`, `KitOverviewView`, and `KitPresenceView`) remain in the codebase as engine-free layout models and regression-tested fallback views, while `RoomDesign.Enabled` (`RoomDesignDefault`, enabled across Editor, development, and release builds) routes all shipped screens through `RoomBar`, `RoomBarView`, `RoomSurface`, and `RoomButton` (`MenuPlane.OlderViewDrawn` logs any unexpected fallback so automated walks fail if a screen drops out of the room kit).

## Connection, pairing, and offline demonstration

### Realtime session, projection, and command submission

- **`RealtimeSession`** runs the WebSocket realtime protocol ([REALTIME.md](REALTIME.md)) on background tasks: `hello` with resume cursor, `welcome` plus `snapshot` or resumed `event` stream, command acknowledgements, 10-second keepalive pings, a 30-second silent-network timeout, and reconnection with capped exponential backoff and jitter. Received messages enter a thread-safe queue drained on the Unity main thread once per frame via `Pump()`, sharing zero mutable state across threads; if a consumer falls more than 10,000 messages behind, the session resynchronizes from a fresh snapshot rather than growing memory without bound.
- **`ClientProjection`** holds `Projects`, `Workstreams`, `Executions`, `Commands`, and `Runtimes`. It mutates only by applying server snapshots and event entity deltas, never deriving domain state locally. It retains pending commands plus the 50 most recent completed commands to match snapshot bounds.
- **`SubmitAsync` and `CommandSubmissions`** send commands over the active session and track local in-flight state (`sending`, `not sent`, `outcome unknown`, `acknowledged`) until the journaled command record arrives in `ClientProjection`. Submission fails immediately without sending when disconnected or when a reconnecting socket has received `welcome` for a different journal before its snapshot is applied. Dropped connections or timed-out acknowledgements raise `CommandOutcomeUnknownException`; resubmitting with the same command UUID safely queries or deduplicates the original attempt. Completion is displayed only after runtime confirmation in projected state.
- **Plain-language connection status (`ConnectionText`, `ConnectionStatus`)** translates transport states into user-facing copy without exposing control-plane internals, raw socket/DNS/TLS exception strings, URLs, or paths ([quest-3-device.md](../validation/quest-3-device.md)). Raw diagnostics go exclusively to `adb logcat` via `ConnectionStatus.Diagnostic` / `ForLog` (`ControlPlaneConnection` logs `Halcyonic: connection <phase>: <detail>` once per settled frame, never logging tokens, titles, instructions, or agent text). Unreachable hosts report `"Can't reach your computer; trying again"` (`ConnectionText.Retrying`), whereas hosts that answered with a refusal (`ConnectionStatus.Answered`, `ConnectionText.Ended`, `ConnectionText.UpgradeRefused`, `ControlPlaneTarget.TurnedAway`, or `ConnectionText.NotThePairedComputer` on a TLS pin mismatch) state the specific recovery action directly. `ControlPlaneConnection` forwards Android pause/resume lifecycle transitions to `RealtimeSession.SetPausedAsync` while ignoring spurious startup resumes.

### USB loopback proof and network pairing

`ControlPlaneTarget` encapsulates how the headset reaches and authenticates with the host computer (`SameAs` compares targets):

- **`Local` (USB development loopback, `ws://` and `http://` on `127.0.0.1` or `[::1]`)**: Before sending the access token on either the WebSocket upgrade (`LoopbackWebSocketTransport` via `WebSocket.CreateFromStream`) or any REST call (`LoopbackProofHandler` speaking raw HTTP/1.1 via `Http1`), `LoopbackProof` challenges the server on that exact TCP socket to prove possession of the shared token ([SECURITY.md](SECURITY.md)). Endpoints using `localhost`, `wss://`, redirects, or missing `Connection: Upgrade` terminate the session immediately, and failed proofs or `401` responses stop reconnection with `AccessRefused`. `ControlPlaneSettings` stores `access-token` in Android app-private `Context.getFilesDir()` (`AndroidTokenStorage` enforces regular-file mode `0600` via `android.system.Os` without following links or pipes; development builds migrate legacy shared-storage tokens inward at startup, and release builds delete any shared token unread via `AccessTokenFile`).
- **`Paired` (local network TLS, every build including release; [ADR 0017](../decisions/0017-pair-a-headset-over-the-local-network.md), [network-pairing.md](../validation/network-pairing.md))**: `Halcyonic.XR.Pairing` (`PairingBootstrap`, `PairingPanel`) exposes `Your computer` -> `Pairing` in `Settings` and opens `PairingColumn` / `PairingCards`.
  - **Discovery (`ComputerFinder`)**: Sends a unicast-response mDNS query for `_halcyonic._tcp.local` to `224.0.0.251:5353` from an ephemeral UDP port (requiring no Android multicast lock) for two seconds on a background thread. Valid `.local` answers become `FoundComputer` offers (`PairingChoice`), never trusted without the pairing code; if multiple distinct hosts, ports, or certificate pin prefixes advertise the same display name, all are retained and marked `SharesItsName` (`Same Name Twice`). When a single unambiguous computer answers (`PairingColumn.PickedForThePerson`), the UI advances straight to the eight-digit keypad under `Your Computer`; multiple answers show `Pick Your Computer`; zero answers show `None Found` with `Type Address`.
  - **SRP-6a exchange (`PairingClient`, `Srp6a`, `PairingCrypto`)**: `PairAsync` runs SRP-6a and mutual proof verification over `/pair` using the eight-digit code from `pnpm pair` (or the host pairing page), sealing a per-device credential bound to the observed server TLS certificate SHA-256 digest (`PairedControlPlane`, persisted atomically by `FilePairingStore` to `halcyonic-pairing.json` in `getFilesDir()`). Refusals and mid-handshake drops map by error code to `PairingCards` titles and recovery sentences (`Computer Not Found`, `Code Incomplete`, remaining attempt pips, or `Reason Unknown`), never echoing unpinned server error text. `Forget this computer` requires a six-second armed confirmation bound to the exact paired address (`PairingNow.Forgets`, `IPairingSettings.Forget`), calls `RevokeAsync` on the host, deletes `halcyonic-pairing.json`, and falls back to any local token or offline playback.
  - **Certificate-pinned transports (`PinnedConnection`, `PinnedWebSocketTransport`, `PinnedHttpHandler`, `PairedReach`)**: Because Unity's Android runtime ignores `ClientWebSocket` certificate callbacks, `PinnedConnection` establishes TCP + `SslStream` directly and compares the server certificate SHA-256 against the stored pin before transmitting application bytes (throwing `CertificateMismatchException` on mismatch). `PinnedWebSocketTransport` upgrades with the device credential and wraps `WebSocket.CreateFromStream`; `PinnedHttpHandler` executes HTTP/1.1 REST calls. `PairedReach` dials the last working address, the originally typed address, and up to eight `.local` / IP addresses refreshed at most every ten minutes from `GET /api/device/listener` (`FilePairingStore.Remember`), keeping the original typed endpoint stable so `connection_key` does not churn when DHCP addresses change.

### Offline recorded run and interactive demonstration

When no control plane is configured, or while the configured target has not yet connected during the app run and fails to answer, `DemonstrationFallback` drives the full client pipeline offline ([ADR 0012](../decisions/0012-a-labeled-demonstration-runs-on-the-headset.md), [ADR 0019](../decisions/0019-the-demonstration-reads-simulated-sources-through-the-real-flow.md), [ADR 0035](../decisions/0035-a-recorded-real-run-lets-anyone-try-halcyonic-before-connecting-a-computer.md), [LOCAL_DEVELOPMENT.md](../runbooks/LOCAL_DEVELOPMENT.md)):

- **Strict separation of recordings (`DemonstrationRecording`)**:
  - `Resources/HalcyonicRecordedRun.json` (`pnpm judge:record`, format version 3, kind `recorded_run`, `IsRecordedRun == true`): replays a sanitized real agent run ([EVENTS.md](EVENTS.md)). Its snapshot must register a real runtime (never synthetic) and carry no simulated intelligence or usage-limit payloads; work displays the `Recorded` mark (`WorkspaceText.ConnectionWords`), answers unrecorded intelligence queries via `DemonstrationReads` as `Not Recorded` in calm secondary text, and responds to interactive presses with `"Not sent to any agent. This run is recorded as it happened, so nothing changes."`
  - `Resources/HalcyonicDemonstration.json` (`pnpm demonstration:record`): a branching event tree on synthetic runtimes (`Practice agent` for directable work and `Practice agent, watch only` for ambient work), labeled `Demo` and `Practice`. Decision nodes hold pre-recorded continuations for approvals, denials, interrupts, preset instructions (`InstructionsFor`), and agent question answers, plus simulated understanding, evaluation, usage-limit, and sample-catalog snapshots (`DemonstrationReads`, `DemonstrationCatalogReads`) and scripted companion turns (`CompanionRecording`). Commands matching an offered branch switch to that node and return a `rejected` ack with code `demonstration` explaining the simulated continuation (`CommandSubmissions.Demonstration`).
- **Playback lifecycle (`DemonstrationPlayer`, `DemonstrationTransport`)**: Assets load on the main thread and parse on a background thread so JSON deserialization never stalls a frame. `DemonstrationTransport` implements `IRealtimeTransport` in memory without sockets or credentials, preserving playback position across Android sleep/resume via the session cursor. When both assets exist, `DemonstrationFallback` disables single-player looping (`DemonstrationOptions.Loop = false`), plays the recorded run first, resynchronizes into the interactive demonstration once the final hold completes, and alternates between them; if `HalcyonicRecordedRun.json` is absent or unreadable, the interactive demonstration loops cleanly via `StateChanges.Rewound`. Timed end-of-node holds pause whenever the wearer is reading an open task file, `New Project`, or a `Settings` leaf (`MenuNavigator.Reading` -> `DemonstrationPlayer.Reading`). The moment a live control plane connects, `DemonstrationFallback` stops offline playback permanently for the rest of the session.

### Development capture presets and generic naming

- **`CapturePresets`** (`#if DEVELOPMENT_BUILD || UNITY_EDITOR` and `Debug.isDebugBuild`, verified absent from release assemblies by `WorkspaceRender.CapturePresetsCheck`): reads Android launch intent extras (`halcyonic.open`, `halcyonic.compose`, `halcyonic.agent`, `halcyonic.arm`, `halcyonic.bar`, `halcyonic.draft`, `halcyonic.heard`, `halcyonic.choose`) once after scene load to navigate presentation state through `MenuDirector` without submitting commands. When `halcyonic.arm` arms an approval confirmation, it waits until the armed state stands unbroken for three seconds across initial room/stage relayouts, re-pressing `Approve` only while unarmed so a preset never confirms an action.
- **`CaptureNames`** (`halcyonic.generic`): replaces vendor and host display strings at draw time (`Coding Agent` for runtimes, `AI Model` for model names/refs, `This Computer` for host chips, `Explanation` and `Measurement` for intelligence sources, and basename-only folder labels in `CaptureNames.Request` and run details) while leaving wire IDs, commands, and agent prose untouched. Its setter `UseGeneric` is compiled out of release builds.
- **Native panel capture (`halcyonic.panelcapture`)**: a separate debuggable-only extra (`PanelBridge.allowCapture`, `PanelCapture`) that allows recording `AgentPanelActivity` within that process; `halcyonic.generic` never disables `FLAG_SECURE` on the native panel.

## Room stage, project places, and character life

### Passthrough, explicit shelf placement, and spatial anchors

`Halcyonic.XR.Room` (`RoomBootstrap`, `RoomPlacement`, `RoomControls`, `RoomPassthrough`, `PassthroughView`, `RoomReader`, `StageAnchors`) is the sole assembly referencing MRUK ([ADR 0015](../decisions/0015-the-stage-stands-on-the-persons-desk.md), [mixed-reality-room.md](../validation/mixed-reality-room.md)):

- **Independent passthrough (`RoomPassthrough`, `RoomStatus`)**: `Settings` -> `Your space` (`SpaceSettings`) controls `Around you` (real room passthrough vs virtual space) independently of whether characters are enabled. Starting passthrough never requests scene-model permission. In development builds (`BoundaryInDevelopmentBuilds`), `Boundary` can temporarily request guardian boundary suppression while passthrough is active, visible, focused, and unpaused; stopping passthrough, losing focus, pausing, quitting, or toggling `Show boundary` restores the boundary immediately ([boundary-visibility.md](../validation/boundary-visibility.md)).
- **Explicit session shelf placement (`AgentShelfColumn`, `AgentShelfDraft`, `AgentShelfSearch`)**: `WorkspacePresentationState` starts with spatial agents off; `Preferred == null` hides `CharacterStage` and its targets without falling back to an unconfirmed floating arc. Enabling `Spatial agents`, opening `Agent shelf`, or pressing `Show this task here` on a live task's Activity page opens a bounded placement preview (`0.4 m` to `2.0 m` horizontal reach, `0.15 m` to `0.9 m` below eye level, `5 cm` / `5 degree` step buttons, and direct `AgentShelfDrag`). `AgentShelfSearch` seeds the preview at `1.9 m` (never closer than `1.2 m` automatically) just outside the console's right edge, stepping outward right then left up to `40 degrees` to find a pose whose entire character, tag, and `New Project` envelope clears the console, `RoomBand`, and any open project screen by at least `1 degree` inside the measured `ViewField`. Pressing `Apply` commits the pose for the tracking session (`OnShelfThisSession`); `Cancel` or focus loss restores the prior state.
- **MRUK surface suggestion and spatial anchors (`StageSurfaces`, `StageAnchors`, `PlacementMemory`)**: Only the explicit `Find a room surface` action inside the placement preview requests scene permission and reads MRUK furniture planes. `RestoreAsync` first attempts to localize a saved `OVRSpatialAnchor` from `PlacementMemory` (storing up to eight recent room anchors and erasing evicted anchors) that still satisfies `StageSurfaces.ShelfFits` and `StillSuits`. Otherwise `StageSurfaces.Choose` ranks upward-facing desk and table planes (`0.4 m` to `0.9 m` away, `0.15 m` to `1.0 m` below eyes, within `45 degrees` of look and `62 degrees` downward pitch, favoring desks near `0.55 m` straight ahead) after verifying the full rectangular shelf clears concave surface edges and tabletop obstacles. Applying an unmoved surface suggestion saves an `OVRSpatialAnchor` (`OnSurface`) under a generation-guarded `placementRun`.

### Project places, seated ring geometry, and team gathering

Every project with work occupies a stable place in the room (`RoomPlaces`, `PlaceRule`, `PlaceBearings`, `PlacePitch`, `CharacterStage.Places.cs`):

- **Project ordering and task tiers (`RoomPlaces`)**: Places retain the order in which projects first had work within the current journal, appending newly active projects at the end so existing places do not shuffle. Within each `RoomPlace`, tasks sort by `CharacterLineup.TierOf` (`NeedsYou` first, then failed/unknown/failing checks, then running work, then most recently updated); if the currently open task falls outside a gathered front, it is promoted to the end of the standing front so an open task always has a standing character.
- **Seated ring bearings (`PlaceBearings`, `StandClearOfNearer`)**: The wearer's own shelf (`OwnPlace`) hosts the selected task's project. Additional active projects stand around the resting workspace heading (`AheadYawDegrees`), keeping the central `FrontClearDegrees = 30` on either side unobstructed and staying within `ReachDegrees = 100` of straight ahead so a seated wearer never turns behind their shoulders. Up to four additional places occupy ring one at `RingOneDistance = 1.4 m` (`Centres` at `-46.8`, `+46.8`, `-83.4`, and `+83.4 degrees`, maintaining at least `GapDegrees = 4` between `32.6 degree` place spans); beyond four, places share each side's `70 degree` arc at `1.4 m` with `4 degree` gaps, and any deeper ring (`RingStep = 0.6 m`, `RingDrop = 0.25 m`) shifts vertically in `0.05 m` steps via `StandClearOfNearer` until its drawn bodies and tags clear the nearer ring by at least `RingClearDegrees = 1` without dropping below `FloorHeight = 0 m`.
- **Row pitch, tag bounds, floor arcs, and `RoomNewProjectPlace` (`CharacterStage.LayPlace`, `LayOwnShelf`)**: Each place bounds individual `RoomNameTag` widths to its share of a full row (`PlaceTagMostDegreesIn`), lays characters at the angular pitch of the widest drawn tag plus `PlateReachDegrees = 0.8` (`PlaceRows`, up to three settlement passes), scales back-row figures by `BackRowScale` while normalizing back-row tag apparent font size to match the front row (`HoldBackRowType`), and raises back rows (`BackRowRiseStep = 0.02 m` up to `BackRowRiseMost = 0.8 m`) until every back-row tag clears front-row bodies by `BackRowClearDegrees = 1`. Every place rests over a linear-blended white floor arc with vertical end ticks (`DrawFloorArc`, `StandShelfFloorArc`, `FloorArcAlpha = 0.064`, `FloorTickAlpha = 0.214`) and a centered project sign (`RoomPlaceSignView` via `StandSignPoints`). On the wearer's own shelf, `RoomNewProjectPlace` (`+` key) sits at the left end and eases further left (`ClearOfTagDegrees = 1.5`) whenever an adjacent tag widens.
- **Crowd gathering (`PlaceForm.Crowd`, `{n} More`)**: Under `PlaceRule.Default`, up to three tasks stand in one row (`Full`) and four or five stand in two rows (`TwoRows`). Larger teams (or narrow places where drawn tags fit only `OneARow`) gather into `Crowd`: the front tasks plus every `NeedsYou` task and the selected task stand, while remaining idle/working tasks gather behind an interactive `{n} More` sign (`MoreOverHeads`, `MoreInDegrees = 3` inside the inner edge). Pressing `{n} More` adds the project to `RoomPlaces.Spread` to stand the full team; `Show Fewer` gathers them again. When the workspace plane grows tall enough to meet the placed shelf, `ShelfAside` rotates the shelf view temporarily along its arc until the page closes, without mutating `OwnShelf`.

### Character flight when a task asks

When an open task displays an agent question or asking moment, `MenuDirector` invokes `CharacterStage.Call(workstreamId, to)` (`RoomMotion.Flight`, driven by `FlightClock` for deterministic Editor verification):

1. **Lift-off and approach**: Whether the character stands on the wearer's shelf or at another project's place (`elsewhereHome`), it lifts off and arcs to the world-space point beside the asking panel, re-evaluating `to()` each frame so it tracks panel placement while clamping height at or below eye level and maintaining at least `FlightClearOfHeadM = 0.5 m` from the wearer's head.
2. **Floor ring and tag choreography**: The character's floor ring (`FloorRingAt = FloorRingHome`) stays behind on the shelf floor and fades out over `FlightBreathSeconds` (`FloorRingKept`) rather than flying through space. Its `RoomNameTag` hides during transit, suppresses its shelf floor stem and diamond (`LabelStemDp = 0`), and fades back in (`TagShown`) resized for the panel's distance once the character settles facing the wearer.
3. **Release home**: Once the question or moment is answered or closed, `CharacterStage.Release()` dismisses the panel first and arcs the character back to its exact shelf or project-place spot, restoring its shelf-scaled tag and (if still waiting) its floor ring. Under `Keep things still` (`GlazeMotion.Still`), flight snaps without motion.

### Character identity and animation

Characters represent `Workstream` objects as procedural bots with living surfaces ([ADR 0013](../decisions/0013-characters-are-bots-with-a-living-surface.md), [character-rendering.md](../validation/character-rendering.md#character-features-on-the-optional-shelf-2026-10-13)):

- **Deterministic identity (`CharacterIdentity`)**: Hashes the UTF-8 `workstream_id` (FNV-1a followed by the MurmurHash3 finalizer) into a body silhouette, one of eight identity hues (spaced at least `25 degrees` away from status hues), light or dark tone, motion phase, blink interval (`3 s` to `7 s`, `Glaze.BlinkSeconds = 0.14 s`), and one of six top features (`None`, `Antenna`, `Ears`, `Sprout`, `Crest`, `Horns`, bounded to `1.32` shell units inside the `0.1` interaction radius). A workstream keeps the exact same appearance across sessions and client versions.
- **Headset-local colour override (`CharacterColourColumn`, `CharacterColourSettings`)**: While a live task's character is visible on the shelf, its Activity page offers `Character colour` (`Original`, `Cyan`, `Violet`, `Pink`). `Preview` updates only that character's body and lightened feature hue; `Apply colour` persists the choice in `halcyonic.character-colours` (versioned local store capped at 64 entries and 64 KiB, scoped to the connection/journal/workstream tuple, never logged); `Cancel`, focus loss, or session change rolls back to the saved hue.
- **Shader and depth composition (`CharacterView`, `CharacterMeshes`, `Halcyonic/Character Body`)**: Each character renders through a single-pass keywordless shader (~160 to 185 arithmetic ops and at most two texture reads per pixel from a startup-baked `128x128` noise texture, shader-antialiased without MSAA, driven via `MaterialPropertyBlock` with zero per-frame heap allocations). The outer shell keeps `_DepthWrite = 1` for rear testing-ring and foreground occlusion, while protruding identity features render at `shell.sortingOrder - 1` on a shared material copy with `_DepthWrite = 0` to eliminate shell/feature edge shimmer. `CharacterView.Grounded` computes the lowest transformed shell vertex after squash, stretch, and rotation each frame so hover, hop, and rise animations never float off or clip through the shelf plane.
- **State cues and living motion (`CharacterPresenter`, `CharacterCues`, `CharacterLife`, `KitFigureLook`)**: Execution status and `ToolActivity` ([EVENTS.md](EVENTS.md)) drive multi-channel cues so state is never conveyed by color alone: `WaitingForHuman` overrides `ToolActivity`, turning the figure to the wearer with a soft white breathing floor ring (`NeedsYouRingColour = Color.white`, `NeedsYouRingBreathSeconds = 2f`, zero backlight behind the body) and `Needs You` written on its `RoomNameTag` (`0.8 degrees` below the feet on the shelf lip plane); `ToolActivity.Running` leans in with reading eye darts; `None` during an active turn sits up and glances aside; `Verifying` spins the testing ring; `Failed` shows surface cracks; `Unknown` shows fog and uneven lids (`_EyeUneven`) while still moving; and disconnected `Stale` (`Last Known`) ghosts the surface and freezes all clocks and transforms in place. `CharacterLife` drives seeded organic floating (`3.2 s`, `5.3 s`, `7.1 s` harmonics with `120 ms` head lag), blinks, gaze holds, observed-pass hops (`RoundStartedAt`), `CharacterMeetings` between co-project tasks, and spatial `CharacterSounds` (`Arrive`, two-note `Voice`, `Hop`, `Fold`).

## Spatial workspace, panels, and multi-screen layout

### Workspace directors, continuity, and input routing

- **`WorkspaceDirector`, `MenuDirector`, and `MenuNavigator`**: `WorkspaceDirector` owns the active `RealtimeSession` view, `ActivityLog`, `EventHistory` (`GET /api/events`, retaining up to 200 entries for the 32 newest executions), and `CommandSubmissions`, hosting `MenuDirector` over `MenuPlane`. Every `IMenuColumn` (`ProjectsColumn`, `TasksColumn`, `FileColumn`, `NewProjectFlow`, `UsageColumn`, `SettingsHubColumn` / `SettingsColumn`, `PairingColumn`, `AskMenuColumn`, `WorkspaceRequestColumn`, `TaskResultsColumn`) receives a `SessionBoundHost` tied to the exact session and journal in which it was created; if the session switches (for example from offline demonstration to live host) or the journal changes, old hosts go inert so demonstration or prior-journal views can never submit to a live control plane.
- **Draw proof, settling, and `FocusGuard`**: A control press or hold acts only on the exact `MenuFrame` or `RoomBar` state last reported `Drawn` after opening/repositioning animations finish (`GlazeButton.Accepting`, `KitPress`, `MenuNavigator.Taking`), preventing double-taps or mid-transition mispresses; safe exits (`Close`, `Cancel`, page turns, and `Stop` via `MenuNavigator.WayOut`) remain responsive immediately without waiting for full read-through. `FocusGuard` (`FocusPresence`) suspends hand visuals, rays, and active `HoldToTalk` captures the instant another window (such as Mac Virtual Display or the Horizon menu) takes focus, enforces a `0.5 s` post-return input guard so a refocus pinch cannot trigger an action, drops half-completed confirmations (`Left`), and folds large panels after `3 s` away while tracking Halora's own `TouchScreenKeyboard` sessions so typing never drops drafts or confirmations.
- **Initial pose, responsive follow, manual drag, and compaction**: `InitialWorkspacePlacement` waits until wearer presence, main camera, tracked head position/rotation, and app focus hold continuously for `0.3 s` before anchoring the workspace ([initial-workspace-placement.md](../validation/initial-workspace-placement.md)). When the wearer turns far enough away and rests within an eligible `+/-25 degree` pitch, responsive recovery (`WorkspaceFollow`, [ADR 0032](../decisions/0032-recover-the-workspace-when-it-leaves-view.md), [responsive-workspace.md](../validation/responsive-workspace.md)) brings an untouched workspace back into view and re-settles input. Grabbing the pill `RoomHandle` (`HandleUnderFootDp` below `RoomBand`) drags the workspace via `MenuDrag` / `PanelDrag`, setting `MovedByHand` so automatic follow leaves the hand-chosen spot untouched until `Settings` -> `Reset Position`. Pressing `Compact` / `Minimize` (`MenuNavigator.Compact`, `ICompactableMenuColumn`) hides the console while preserving open `FileColumn` drafts in memory; pressing the controller Menu button or left-hand palm-up pinch (`Button.Start`, `MenuDirector.MenuFromAnywhere`, [xr-menu-input.md](../validation/xr-menu-input.md)) reopens the menu from anywhere or returns from the menu to `Projects`.
- **Durable workspace continuity (`WorkspaceContinuation`, `WorkspaceViewStorage`, `WorkspaceViewRecovery`)**: Ordinary unsent instruction and workspace-request drafts (up to 32,000 characters, spoken-origin flag, editor part, active `task | request` surface, and pre-persisted `pending_command_id` UUID for lost-ack recovery) serialize into the shared 256 KiB `WorkspaceContinuation` contract keyed by SHA-256 `connection_key` (`["halcyonic-workspace-v1", scheme, host, port, deviceId, certificateSha256, credential]`, never logging or exporting raw credentials). Unity persists all retained task views atomically up to 4 MiB in app-private `halcyonic-unity-workspace-views.json` (`WorkspaceViewStore`, `WorkspaceViewBindings`), separate from native panel storage. On startup, once `RealtimeSession.SnapshotCurrent` confirms the welcome head watermark, `MenuDirector.RecoverViews` imports matching views with fresh read/input proof, fronting the previously active task beside `Projects` only if it is actively running or waiting on the wearer (`WorkspaceViewRecovery.FrontsAtLaunch`) and keeping idle or stale-execution drafts inspectable under `Tasks` -> `Saved drafts`. Approval decisions, question answers, secret inputs, and armed confirmations are never persisted.
- **Curved interaction and seated rays (`CurvedDrawing`, `SeatedHandRay`, `GazeHover`)**: `CurvedDrawing` bends `MenuPlane` surfaces and sheared `GlazeRuns` text meshes onto `PlaneCurve` at `0.46 m` touch distance ([ADR 0034](../decisions/0034-the-workspace-is-one-continuous-gentle-curve-centred-on-the-eyes.md)), matching visual curvature with Interaction SDK `ClippedCylinderSurface` hit patches on `PointerTarget`. `SeatedHandRay` (`SeatedPointing`) projects rays from `0.40 m` below, `0.10 m` behind, and `0.13 m` lateral to the eyes through the index knuckle so a forearm resting on a desk points naturally, turning off when the palm faces within `20 degrees` of the floor (typing/resting) or toward the eyes (system gesture) ([workspace-interaction.md](../validation/workspace-interaction.md)). `PeekChoice` and `GazeHover` ([ADR 0014](../decisions/0014-hand-interaction-through-the-interaction-sdk.md)) require `0.4 s` head-gaze dwell within `10 degrees` at head angular speeds below `20 deg/s` before fading in a character `PeekCard`, allowing look-and-pinch opening only when no workspace is open and no hand ray or poke is on a target (`OnboardingHint` retires permanently after the first open).

### Dark-glass surfaces, thin-glass actions, and the no-hue invariant

- **Geometry and adaptive plane width (`RoomGeometry`, `PlaneWidth`)**: At `0.46 m` touch distance (`1 dp = 0.0625 degrees`), the workspace pair spans `43.5 degrees` (`440 dp` information panel, `16 dp` gap, `240 dp` action column) with its foot line pitched at `-17.6 degrees`, the home action row at `-23.5 degrees`, and `RoomBand` at `-24.5 degrees`. `MenuPlane.ConsiderForm` selects the widest panel step (`440`, `400`, `360`, `320`, `280`, `240 dp`) at or above the reading floor (`360 dp` at `Standard`, `400 dp` at `Larger`) that fits inside the Quest 3S field and clears placed shelves; if even the floor meets a shelf, the shelf yields (`ShelfAside`) so reading width is never crushed.
- **`RoomSurface` (`Halcyonic/Room Glass`, `AskGlass`)**: Draws dark glass (`#121212` face at `0.918` linear alpha, matching `rgba(12, 14, 22, 0.72)` within `7/255` across `#1E1C1A`, `#B9AE9E`, and `#EEEEEE` rooms without backdrop blur), a `1 dp` top-to-foot rim hairline (`#919191` easing to `#2C2C2C`), exponent-4 squircle corners (`32 dp` panels, `22 dp` bars, `14 dp` tags), and an `8%` white inner hairline above the panel's single status/prompt sentence (`InnerBar`).
- **`RoomButton` (`Halcyonic/Room Halo`) and `RoomGlyphView`**: Actions stand on opaque thin-glass capsules (`#272727` at rest, `#3C3C3C` pointed with `1.03x` scale, `#323232` held at `0.96x` scale; `48 dp` column core / `32 dp` chip / `20 dp` vector glyph, or `60.8 dp` home core / `44 dp` chip / `24 dp` glyph; minimum `60.8 dp` hit target and `12 mm` / `24 dp` target separation). Each moment's single primary action uses a lighter thin-glass plate (`#474747` at rest, `#555555` pointed) with white vector glyph and white words, never a colored fill or outline. Unavailable actions are omitted rather than drawn disabled; `Confirm` behind a safety lock displays a `2 dp` white progress ring `4 dp` outside its chip (`ConfirmLockSeconds = 0.7 s`) while rejecting presses until full. Secondary metadata chips (such as agent approval level) float `10 dp` beside the core on `#2D2D2D` (`78%` alpha, `17 dp` label type) without widening the button's hit target (`Aside`).
- **`RoomBar`, foot-row actions, and `RoomBand`**: `RoomBar.Of` binds task loops (`RoomBar.Tasks`), contextual task moments (`RoomBar.Moments`), and general menu frames (`RoomBar.OfFrame`: `Projects`, `Tasks`, `Folders`, `Menu`/`Usage`, `Pairing`, `Agent`, `New Project`, `Ask`, and `RoomBar.General` for settings and side panels) onto `RoomCardView` cards. Plain panel actions sit in a single right-aligned foot row inside the panel glass (`RoomBar.ActionsAtFoot`, `RoomBarView.LayPair`, dismiss first and main action last), keeping a side column only for marked question choices, `RoomBand` part paging, route lists, or rows exceeding the bar envelope. Below the pair, `RoomBand` (`#0E0E0E` sRGB ground at `0.72` alpha, `0.86` for spoken draft subtitles, `880 dp` / `55 degrees` wide with `600 dp` text measure) displays agent prose and question prompts up to three lines per part, splitting multi-part text at sentence boundaries (`RoomWords.SentenceEnds`) with `"Part 1 of N"` at its lower-right foot and `"Next Part"` / `"First Part"` paging.
- **No-hue chrome invariant (`KitRender.ChromeTakesNoHue`, [STYLE.md](../product/STYLE.md))**: Zero shipped chrome carries chromatic hue. State, hierarchy, and selection are communicated through form, typography weight, white brightness, and motion rather than color. `KitRender.ChromeTakesNoHue` inspects every `KitGlass`, `Surface`, `RoomSurface`, `RoomShape`, `RoomBand`, `RoomNameTag`, and `TMP_Text` across `KitRender.Check` and `JudgeRoomWalkCheck`, failing if any chrome element above near-black (`V > 0.04`) exceeds `HSV saturation 0.12` (or if `KitWorkspaceHost` falls back to legacy kit views). Only procedural character bodies/figures, a previewed app's own content, and syntax-highlighted code tokens are exempt.

### Multi-screen room layout and contextual moments

`WorkspacePresentationState` and `RoomLayout` ([ADR 0040](../decisions/0040-the-headset-is-a-room-of-projects.md)) coordinate progressive spatial surfaces around the wearer, keeping every interactive surface within OpenXR ray-cast reach (`0.8 m` to `3.0 m`):

- **Up to three simultaneous project screens (`ScreensMost = 3`)**: Opening a project screen (`ShowProjectScreen`, triggered from `Show Project Screen` on a task's rail) adds the project to `ScreenProjectIds` up to `ScreensMost = 3`. Attempting to open a fourth screen never silently evicts an open project; `ScreenRefused` surfaces `"Close a screen to open another"` (`CloseAScreen`) until one is closed.
  - **Foreground work screen (`MenuPlane.ShowScreen`, `KitScreen`, `KitScreenBar`)**: The most recently summoned or selected screen (`ScreenProjectId`) stands flat `2.0 m` ahead along the console bearing (`56 x 31.5 degrees` at `Standard`, narrowed to `48 x 27 degrees` at `Larger` so a placed shelf still fits inside the Quest 3S field, pitch-clamped within `+/-25 degrees`), with its command bar `2 cm` in front and `0.75 degrees` below its bottom edge. Showing the foreground screen tucks the workspace console into compact aside without losing drafts; closing the screen (`KitScreenAction.Close`) restores the console.
  - **Team screens (`MenuPlane.ShowTeamScreens`, `RoomLayout.TeamScreen`, `RoomLayout.Screens`)**: The remaining open project screens stand flat over their respective project teams at `TeamScreenDegrees = 24` width, lower edges `TeamScreenLowestDegrees = 8` above eye level (`3 degrees` clear of lifted back-row tags at `Larger`). `RoomLayout.Screens` solves least-squares bearings (pool-adjacent violators) near each project's place while enforcing `ScreensGapDegrees = 4` between screens, keeping edges outside `ClearAheadDegrees = 30` and inside `SeatedReachDegrees = 100` (`ScreensPaged` appends `"{n} More"` beneath the outermost screen if more screens wait than the arc holds). Pressing any team screen brings it forward as the active work screen.
- **Contextual moment cards and heads-up leash (`KitMomentCard`, `HeadsUpLeash`)**: While no task file is open (`BesideTask == null`), `MenuDirector.UpdateProgressiveSpatial` projects a `23 degree` `KitMomentCard` in `RoomLayout.MomentSlot` (`1.5 degrees` clear of the character's body and tag on the side toward the wearer's gaze) whenever a placed task reaches `ActionRequired` or is inspected via `InspectMoment`. `HeadsUpLeash` bounds at most two peripheral HUD items at `1.0 m` (`+/-35 degrees` yaw, `-20 degrees` pitch) with a `30 degree` head-turn dead zone and a `0.25 s` fade during brisk head movement.

## Directing work: instructions, approvals, questions, and limits

### Untrusted text rendering

Every string Halora did not author (project/task titles, objectives, agent messages, tool names, approval commands and inputs, file paths, runtime/model names, intelligence conclusions, companion replies, and transcribed or typed user text) passes through `LabelText` and `LineWords` ([SECURITY.md](SECURITY.md), [outside-text-audit.md](../validation/outside-text-audit.md)):

- **`LabelText.Plain` and `ForTextMeshPro`**: Using a fixed Unicode 17.0 classification table so .NET tests and Android builds behave identically, `Plain` collapses single-line non-space whitespace into a single ASCII space and spells every control, format, bidirectional override, default-ignorable, braille-blank (`U+2800`), noncharacter (`U+FDD0..U+FDEF` and plane-ending code points), unpaired surrogate, and Private Use Area code point (`U+E000..U+F8FF` and planes 15 to 16, preventing untrusted text from spoofing Halora's PUA icon glyphs) visibly as `‹U+XXXX›`. `ForTextMeshPro` doubles every backslash for labels configured with `richText = false` and `parseCtrlCharacters = true` (`GlazeText.SetLiteral`), rendering markup and escape sequences verbatim ([workspace-interaction.md](../validation/workspace-interaction.md)).
- **`LineWords` and `HostPlain`**: Tracks Halora-authored runs (`Ours`, `Written`) separately from outside-text runs (`Theirs`, `TheirName`, `Unspelled`), truncating only outside runs at whole code-point boundaries (`CutToFit`) so Halora's own labels are never clipped. `Ours` throws if `LabelText.Plain` would alter a constant; host-supplied status and review strings use `LineWords.HostPlain`, which safely normalizes non-breaking spaces or tabs instead of throwing during release rendering while incrementing `LineWords.Folds` (logged by kind only and failed in `KitRender.Check`).

### Instructions, New Project, runtime faces, and approval levels

- **Instruction drafting and explicit send (`FileColumn`, `FileInstruction`, `WorkspaceSteering.SendInstruction`)**: At rest, `Hold to Talk` and `Type` (`Choose Instruction` when no keyboard is available or during preset playback) float unlit at home size. Keyboard input and voice transcription populate only the local `FileInstruction` buffer bound to the current execution, never auto-submitting. Spoken drafts (`DraftSpoken`) omit the typing caret, display `Read Full Instruction` / `Send Heard Instruction?`, and offer `Talk Again` alongside `Send Instruction` and `Cancel`. Drafts exceeding eight panel lines paginate at seven content lines plus pager (`0.4 s` `TurnGuard`), enabling `Send Instruction` (and policy `Confirm` when required) only after every part has been drawn in order on the active layout (`MenuDirector.RowsOf`). `TaskPictures` decodes up to eight attached project photo/video stills (`ControlPlaneApi.GetPictureAsync`, [ADR 0058](../decisions/0058-an-instructions-pictures-come-from-the-projects-folder-and-reach-the-runtime-as-the-bytes-the-host-read.md)) onto `RoomCardView.Pictures`.
- **Generic runtime faces and between-run switching (`RuntimeFaces`, `KitPresenter.ChipsOf`, `AgentColumn`, [ADR 0033](../decisions/0033-approvals-declare-whether-commands-leave-the-sandbox.md), [ADR 0043](../decisions/0043-a-person-may-let-a-tasks-agent-work-without-asking-where-its-runtime-keeps-it-in-bounds.md))**: Surface chips name agent apps by role (`RuntimeFaces.Head`: `Local Models`, `Hosted Models`, `Your Model Setup`, `Signed-In App`, `Practice Run`, `Coding Agent`) and host environment as `This Computer` (`ApprovalMayLeaveSandbox == true`), `Sandbox` (`false`), or omitted when undeclared, keeping vendor names inside pickers and run details. While an execution is active, chips lock as read-only facts. At rest (`KitPresenter.AtRest`), pressing the agent/level control opens `AgentColumn` (`ProjectChoices` persisted per project in `halcyonic.project-choices`), allowing the next instruction (`Start New Run`) to start a fresh execution on a chosen runtime, `Listed` model (`GET /api/runtimes/:id/models`, [ADR 0016](../decisions/0016-a-person-chooses-a-runtimes-model-from-its-own-list.md)), and approval level (`Ask First` by default; `Never Ask` only when `offers_never_ask` is true and the level is displayed prior to submission; or `Plan First` via `PlanStart` when `offers_plan` is true, sending `plan: true` and later offering `Carry Out Plan` with `leave_plan: true` once `RunStart` reaches `Plan Ready`). Changing runtime, model, or level while an instruction confirmation is armed cancels the confirmation so the sent level always matches what was shown.
- **`New Project` and `BuildSequence` (`NewProjectFlow`, `NewProjectScreens`, `NewWorkDraft`, `NewWorkReview`, `StarterChoice`, `FolderConnect`)**:
  - **Idea and companion (`ProjectIdea`, `CompanionExchange`, [ADR 0025](../decisions/0025-the-companion-is-a-local-model-whose-exchange-stays-on-the-headset.md))**: Accepts a free-form spoken/typed objective (titled deterministically up to 60 characters via `NewWorkDraft.TitleOf`, stripping URL credentials/queries and matching `fixtures/titles/cases.json`), four deterministic non-AI guide questions, or a headset-kept local Ollama `CompanionExchange` (bounded to 20 messages / 2,000 chars each, explicitly marked as AI suggestions with `Use my words` retained). Drafts persist for 7 days per journal via `CreationDrafts`.
  - **Smart defaults, folders, and starters ([ADR 0020](../decisions/0020-a-project-works-in-one-host-approved-folder.md), [ADR 0037](../decisions/0037-new-vr-apps-start-from-a-host-vetted-web-starter.md))**: Preselects the last real runtime used, its last or preferred local tool-calling model (off-computer models are never preselected and require a two-press data-egress warning), and a sanitized `New Folder` or `New VR Starter` (`iwsdk-vr`, plus any installed starter from `GET /api/starters` via `StarterChoice`) inside host-approved roots (`GET /api/locations`; `ProjectsColumn` also connects existing unused repositories via `Connect a folder` / `FolderConnect`). If a choice is still missing on the recap, `NewProjectScreens.WayOn` promotes that picker (`Choose Folder`, `Choose Agent App`, `Choose Model`) as the primary button.
  - **Whole-card start vs paged review (`RecapShownWhole`, `NewWorkReview`, `BuildSequence`)**: When the recap card renders completely uncut (`RoomCardView.LaidWhole`, single-page description, unambiguous folder/model, and zero warnings), pressing `Start Task` / `Start Building` dispatches immediately; otherwise `NewWorkReview` spells non-ASCII/control characters in ASCII and requires paged `0.4 s`-guarded read-through before enabling confirmation. `BuildSequence` chains `project.create` (or `project.set_location` carrying `MoveReview` digest from `ReviewLocationAsync`, [ADR 0051](../decisions/0051-a-paired-device-acts-on-files-only-with-the-review-it-read.md)) -> `workstream.create` -> `execution.start`, advancing each step only after `ClientProjection` records the prior command completed, and persisting any unknown-outcome command ID per journal (`KeptUnknownStart`, `Check Last Start`) to prevent accidental duplicate creation.

### Literal approval wells and multi-part confirmation

`RoomBarState.Request` (`KitNeed`, `WorkspaceSteering`, [ADR 0065](../decisions/0065-a-request-too-long-to-show-whole-is-denied-by-the-host-with-its-reason.md)) renders pending runtime tool approvals:

- **Literal command and input well (`LineWords.Literal`, `GlazeRuns.SetWell`)**: Shell commands render `ToolUseSubject.Command.Text` alone in `KitMono` (`19 dp` on `28 dp` lines) inside the recessed dark well, with the agent's `Summary` (`WithoutCodeMarks`) above in body type; structured non-shell tool calls (`ToolUseSubject.Inputs`, such as ACP tool invocations) render each input name in `78%` white above its raw JSON value under the dialog title `WorkspaceText.Heading`. `LineWords.Literal` styles host-supplied and raw hazard characters as `50%` white `WordRun.Mark` glyphs: `↵` before line feeds (accompanied by `"↵ marks a new line."` above the well), `⇥` for tabs, `‹U+0020›` for leading, trailing, or pre-newline spaces, and `‹U+XXXX›` for control, bidi, or format code points, so multi-line or homoglyph-padded commands cannot masquerade as benign single-line commands.
- **Unapprovable requests and confirmation rules**: When `ApprovalView.approvable` is false (such as host-truncated or incomplete requests), only `Deny` is offered alongside `WorkspaceText.OnlyDeny`. When a complete request fits within a single eight-line panel part and has been drawn whole, pressing `Approve` or `Deny` dispatches `execution.respond_to_approval` directly (`DecideOnPress`, disabled during `CapturePresets`). Multi-part requests paginate eight lines per part under confirmation: `Deny` can be confirmed from part 1 immediately so dangerous requests can be refused without reading every page, whereas `Approve`'s `Confirm` appears only after every part has been drawn in order (resetting the `15 s` confirmation timeout on each page turn and invalidating read proof if text scale changes via `ReadAgainAtNewSize`), guarded by the `0.7 s` `ConfirmLockSeconds` ring. While an approval response is in flight (`ApprovalInFlight`), actions clear to `Sending` until `runtime.approval.resolved` arrives.

### Agent questions and answer validation

`QuestionDraft`, `QuestionPlace`, `FileQuestion`, and `RoomBarState.Question` ([ADR 0022](../decisions/0022-agent-questions-reach-the-person.md)) enforce contract-valid, fully read answers to `ExecutionView.PendingQuestions`:

- **Prompt band and adaptive choice layout**: The agent's question prompt appears on `RoomBand` (requiring every three-line part on the band to draw before the frame counts as read). Plain short choices stand as marked `RoomButton` items (`22 dp` circle for single-select, squircle for multi-select) in the `240 dp` column when total column controls do not exceed four; prompts with option descriptions or more than four controls lay out as full-width pressed rows on `RoomCardView` (`RoomBar.Asking`, eight lines per page) so the action column never widens.
- **Custom answers, mandatory review, secrets, and duplicate labels**: Free-text prompts offer `Write Answer`, opening a dedicated editor (`Use Answer` saves only after all buffer parts are read; `Hold to Talk` is hidden when `FreeText == false`). Every question requires a final `Review Answers` page enumerating all selections and custom words before exposing `Send Answer` (`CommandSubmissions.AnswerPending` blocks duplicate sends; `question_unconfirmed` / `answer_ambiguous` report `"Not confirmed: the agent may or may not have your answer"`). Questions requesting a secret (`secret: true`) or offering only indistinguishable normalized labels (`OffersALabelTwice` via NFC `WorkspaceText.AsShown`) suppress answer inputs, keyboard, and `Hold to Talk` so secrets cannot enter the journal and ambiguous labels cannot be guessed, offering `Stop` (and a `Duplicate Choices` explanation page when `ReadsAlike` leaves another path) as the safe exit.

### Spending limits, waiting instructions, workspace requests, and action reviews

- **Spending limits (`SpendingLimit`, [ADR 0062](../decisions/0062-a-tasks-spending-limit-is-the-apps-own-stop-handed-only-what-is-left.md))**: On runtimes declaring `offers_spending_cap`, `New Project` offers `Spending Limit` (`No Limit`, `$1`, `$5`, `$10`, showing `Stops Near $5.00` on the recap and the host's last-step estimate note in review). When an execution's `spending_cap` reaches `reached` (or `waiting` with unknown spend after a host restart), the composer displays `At Spending Limit` (`Spent $X of $Y`) or `Spending Not Known`, presents `Spend Up To` (`$1 More`, `$5 More`, `$10 More`, `"Counts from now."`), and locks `Send Instruction` with `Choose an Amount First` until the wearer explicitly picks an increment (`FileInstruction.NewLimit`, `WorkspaceSteering.ArmedLimit`; assistants never propose limits).
- **Turn-queued instructions (`WaitingInstructions`, [ADR 0056](../decisions/0056-an-instruction-sent-during-a-turn-waits-for-it-on-a-runtime-that-cannot-steer.md))**: While a turn runs with entries in `ExecutionView.queued_instructions`, the working bar displays `Waiting` (`"Each is sent when this turn ends."`), pairing each queued command ID with in-memory `CommandSubmissions.InstructionOf` text (or `"Your Instruction"` if sent elsewhere). Opening an item shows `Waiting for Its Turn` with one-press `Drop` (`execution.drop_queued_instruction`). At rest, any queued instruction that failed unsent (`queued_*` failure code, `UnsentInstruction.Of`) leads the result card as `Not Sent` with `Send Again` and `Back`.
- **Workspace assistant requests and model choice (`AskColumn`, `AskMenuColumn`, `WorkspaceRequestColumn`, `AssistantPlace`, `UsageColumn`, [ADR 0030](../decisions/0030-workspace-requests-use-a-journaled-agent-tool-loop.md))**: `Ask` (scoped to a task, project, or `All Work`) tracks journaled assistant tool loops (`Writing`, `Sent`, `Thinking`, `Waiting`, `Needs You`, `Answered`, `Not Answered`), keeping model-reported replies on `RoomBand` with `"Answered by {model}"` at the foot and routing `workspace.request.resume` / `workspace.request.cancel` without interrupting executor turns. `UsageColumn` renders provider quota gauges from `GET /api/usage-limits` (`UsageLeftPresenter`: `"At most X% left"`, rounded up, omitting expired windows and never inferring `0%`) alongside `AssistantPlace` (`GET /api/workspace/agent` and `assistant_models`, dispatching `Use Model` through `WaitingReview`).
- **Unified host action review (`ReviewCard`, `ActionReview`, [ADR 0060](../decisions/0060-the-computer-says-what-can-be-done-here.md))**: Any host-reviewed action renders through `ReviewCard` using `ReviewKinds` glyphs and `LineWords.HostPlain`: consent-critical warnings (`ConsentFirst`: unasked execution, out-of-folder access, irreversibility, public publishing, or monetary cost) appear immediately beneath the title under `Check First`, while operational warnings follow the summary (`StatusAfter`); affected items paginate five per part; any outbound model-written text (`ActionReview.said`) renders verbatim via `LineWords.Literal` across all parts before `Confirm` (carrying the review digest) appears on the final part.

## Comfort, typography, sound, and voice

### Typography and static SDF font atlases

- **Six kit faces plus title and icon atlases (`KitFontAtlas`, `InstrumentFontAtlas`, `GlazeIconAtlas`)**: `KitFontAtlas` builds six static TextMeshPro SDF atlases (`72 pt`, padding `9`, `SDFAA`, smallest fitting size across `1024x1024`, `2048x1024`, and `2048x2048`, with OFL license files verified byte-for-byte in `Assets/StreamingAssets/Halcyonic-Licenses/`): `KitDisplay`, `KitTitle`, and `KitReadingStrong` (`Inter-SemiBold`), `KitReading` (`Inter-Regular`), `KitLabel` (`Inter-Medium`), and `KitMono` (`JetBrainsMono-Regular`). `InstrumentFontAtlas` builds static `InstrumentType` (`Rajdhani-Medium`), falling back to `KitTitle` for 16 accented/symbol glyphs Rajdhani omits (`InstrumentFontAtlas.Lacks`).
- **Glyph coverage and fallback chain**: Every static kit face bakes printable ASCII, typographic punctuation, Latin-1 and Latin Extended-A (`KitGlyphs.Latin`), and the literal well's angle quotes and tab arrow (`‹`, `›`, `⇥`); Inter faces also bake the newline mark `↵` (`U+21B5`), while `KitMono` reaches `↵` and `Ĳ`/`ĳ` (`MonoLacks`) through its first fallback `KitReading`, followed by `Liberation Sans` dynamic fallback for scripts outside Latin Extended-A. `GlazeIcons` renders 13 static UI symbols from `Material Symbols Rounded` (`256x256` atlas, `GlazeIconGlyphs`, never mixed into prose labels; [material-symbols.md](../validation/material-symbols.md)), while room actions draw procedural geometry via `RoomGlyphView`. `KitFontAtlas.Check` and `InstrumentFontAtlas.Check` rebuild every face in memory and verify glyph tables, metrics, fallbacks, and raw atlas pixels byte-for-byte against committed assets (`FontAssetsKept` prevents Editor renders from dirtying fallback assets).
- **No TMP bold/italic tags (`GlazeText`)**: Because custom static faces carry no separate italic or bold sub-assets, TextMeshPro's `<b>` and `<i>` modes fail to find an ellipsis glyph and silently switch to hard clipping. Strong text uses dedicated SemiBold faces or shader weight (`GlazeText.SetStrong`), and outside-text provenance shear is applied directly to laid-out character vertices (`GlazeText.Lean`). Labels instantiate awake before parenting (`GlazeText.AddAwake`) so off-screen measurement matches visible bounds, and rebuild meshes only when text, style, or dimensions change.

### Comfort

`Comfort`, `ComfortSettings`, and `ComfortControls` persist three immediate device-local comfort controls, backed by automated legibility and contrast gates:

- **Text scale (`Standard` and `Larger`)**: `Standard` sets room reading copy in `Inter Regular` at `20 dp` on `28 dp` lines (`-0.6%` tracking; labels in `Inter Medium` spaced capitals at `18 dp`; code in `JetBrains Mono` at `19 dp`), holding every glyph at or above the `14 dp` (`0.875 degree`) apparent angular floor (`MenuPage.LeastEm`). `Larger` scales reading sizes, chips, glyphs, and interior padding by `1.15x` (`Comfort.LargerTextScale`, `RoomType.Scaled`), widens the minimum panel floor from `360 dp` to `400 dp`, narrows foreground project screens from `56 degrees` to `48 degrees` so shelves still fit, re-wraps `FileChangeColumn` code/diff views, and invalidates unread agent request/question part proofs (`ReadAgainAtNewSize`) so re-paginated words are never confirmed unseen. Every Editor render harness executes at both `Standard` and `Larger` against Quest 3S field bounds (`ViewField`, `FieldChecks`, `1.5 degree` lens-edge margin) and enforces at least `4.5:1` linear contrast over glass across dark, warm, and bright backgrounds.
- **Reduced motion (`Keep things still`, `GlazeMotion.Still`, [ADR 0027](../decisions/0027-the-headset-moves-only-to-answer-the-person-or-show-a-wait.md))**: Stops all autonomous motion (`Starting`/`Working` icon rotation, `NeedsYouRing` floor breathing, `Hold to Talk` listening pulse, character floating/blinking/wandering/accents, and surface shader flow/fog clocks; `GlazeShimmer` switches from a vertex-alpha sweep to a steady highlight; character flight, `ShelfAside`, and `RoomWritingArc` shifts snap without travel; `RoomWritingPanel` cross-fades in `200 ms`). Motion directly answering a wearer's press or drag continues, and `PanelBridge.setMotionStill` syncs the preference to the native Android panel.
- **Sound level**: Steps `AudioListener.volume` across `On` (default `0.5` serialized gain), `Quieter` (`-6 dB`, half amplitude), and `Off`.

### Sound

`Halcyonic.XR.Sound` (`SoundBootstrap`, `StageSound`, `CharacterSoundPlayer`, client-core `GlazeSynthesizer`, `SoundCueSelector`, and `CharacterSounds`) synthesizes all spatial audio procedurally in code with zero recorded sample assets ([sound-rendering.md](../validation/sound-rendering.md), [meta-xr-audio.md](../validation/meta-xr-audio.md)):

| Cue | Trigger | Timbre | Spatial origin |
| --- | --- | --- | --- |
| `Working` | Round starts or resumes after an answer | Soft felt double tap | Task character |
| `Checking its work` | Verification/test run starts | Four muted taps, up and back | Task character |
| `Waiting for you` | Execution blocks on approval or question | Two rising ceramic strikes; second rings | Task character |
| `Finished this round` | Round completes (completion is not correctness) | Two-note fall onto home pitch | Task character |
| `Couldn't finish` | Execution round fails | Dull cracked strike, then lower drop | Task character |
| `Can't tell yet` | Execution enters `unknown` state | Unsettled pitch strike | Task character |
| `Stopped` | Runtime confirms interrupt | Strike damped flat by hand | Task character |
| `Last known` | Live session drops to retry or refusal | Six-note muffled chord fading | Stage center (`60 deg` spread) |
| `Open` / `Close` | Workspace opens from or collapses to character | Chord unfolding / folding back | Workspace (`0.6 m` ahead) |
| `Approve` / `Deny` | Decision submitted (sent, not yet confirmed) | Warm dyad / damped step down | Workspace (`0.6 m` ahead) |
| `Tell it` / `Send answer` | Instruction or question answer submitted | Three light taps / tap onto warm note | Workspace (`0.6 m` ahead) |
| `Stop` | Interrupt submitted | Flat damped press | Workspace (`0.6 m` ahead) |
| `Touch` / `Not now` | Generic accepted press / unavailable button press | Single `D4` felt tap / quiet damped step | Pressed button |

`SoundCueSelector` and `GlazeSynthesizer` enforce calm-audio invariants:

- **Synthesis and startup pre-rendering**: `GlazeSynthesizer` models six inharmonic ceramic modes with beating twins, felt mallet thuds, pink-noise band-pass sweeps, `mulberry32` deterministic seeding, K-weighted loudness normalization (`-20 LUFS` for `Waiting for you` down to `-32 LUFS` for `Touch`, spectral centroids averaging `347 Hz` and capped at `649 Hz`, peak `<= 0.6`), and FFT overlap-add convolution with a `1.3 s` darkening room impulse response. `StageSound` synthesizes all 87 clips (14 per-note cues across 6 D-major pentatonic home notes `A3`, `B3`, `D4`, `E4`, `F#4`, `A4`, plus `Last known`, `Touch`, and `Not now`) on a startup worker thread (`~17.7 MiB` PCM) and uploads four `AudioClip`s per frame on the main thread, scheduling playback via `AudioSource.PlayScheduled` with zero runtime synthesis or `OnAudioFilterRead` overhead.
- **Scheduling, focus, and HRTF spatialization**: Ongoing work and test execution stay silent; simultaneous cues stagger by at least `300 ms` in urgency order; identical character cues within `10 s` drop unless the wearer just acted on that task; snapshots, resynchronizations, and demonstration rewinds are silent. No cue starts while unfocused (`FocusGuard.InputSuspended`), except system-keyboard submissions which wait up to `2 s` for focus return (an optional `waiting-for-you-sound-while-away` data-dir flag enables a single `60%` `Waiting for you` chime while unfocused, [OPEN_QUESTIONS.md](../product/OPEN_QUESTIONS.md)). Character voices (two `AudioSource`s per body, full level within `2.5 m`), workspace actions, and button taps route through Meta XR Audio's HRTF spatializer (`com.meta.xr.sdk.audio` 85.0.0, switchable to Unity panning via `sound-panned`, verified both ways by `SoundCheck`). Every cue has a visual twin so Halora is complete on mute.

### Voice

Halora supports push-to-talk dictation transcribed by `whisper.cpp` on the host computer ([ADR 0021](../decisions/0021-speech-becomes-a-draft-transcribed-on-the-mac.md), [voice-transcription.md](../validation/voice-transcription.md)), with distinct build gates for immersive Unity XR and the native Android panel:

- **Immersive Unity XR (`HoldToTalk`, `MicrophoneAsk`, `MicrophoneAtOpen`, `SpeechClip`, every Unity build)**:
  - **Shipped in every Unity APK**: `HoldToTalk` (`Offered => true`) compiles into both development and release builds, and `QuestBuild.BuildReleaseApk` fails and deletes any release APK whose manifest omits `android.permission.RECORD_AUDIO`. `MenuDirector.VoiceOffered` exposes `Hold to Talk` only when connected to a live computer (`!Demonstration`), so standalone headsets running offline recordings never prompt for microphone access.
  - **Permission and capture**: `MicrophoneAtOpen` / `MicrophoneAsk` explains microphone usage once on the first eligible open (`halcyonic.noask=true` skips the open prompt; `MicrophoneAtHold` handles first-hold requests and explains system-blocked states). Holding `Hold to Talk` for `0.3 s` (`GlazeButton.Holds` / `RoomButton`) starts non-looping capture up to `30 s` (`SpeechClip.MaxSeconds`), sampling a `50 ms` RMS window into a 26-bar `-54..-12 dBFS` meter (`LevelHistory`) while displaying `Listening`. Releasing under `0.5 s` reports `TooShort`; pointer exit, cancel, text-size change, or `FocusGuard.InputSuspended` stops recording and discards the audio immediately without network transmission.
  - **Resampling and draft review**: `SpeechClip.Encode` mixes channels to mono, resamples to `16 kHz` 16-bit PCM WAV, and posts to `POST /api/transcriptions` (`ControlPlaneApi.TranscribeAsync`). Returned `HeardTranscription` text is untrusted (`LabelText`), scoped by per-recording `MenuVoice` leases so delayed responses never land in a different task or field, and placed into the local draft marked `Spoken` (never auto-submitted; if whisper is unconfigured on the host, `VoiceText` shows `Voice Not Set Up · Type Instead`).
- **Native Android panel (`PanelVoice`, `PanelVoiceCapture`, debuggable builds only; [native-panel-voice.md](../validation/native-panel-voice.md))**: Inside `apps/xr/Android/panel`, held dictation remains gated to debuggable non-preview APKs (`PanelCapture`). The first `0.3 s` hold requests runtime permission without recording; subsequent holds record `16 kHz` mono PCM16 up to `30 s` on a dedicated worker (`30 s` HTTP deadline, `64 KiB` response cap over pinned TLS or USB `PanelProof`) and append spoken words (`Hold to add words`) only if the complete connection/journal/project/task/execution/editor/starting-draft tuple and Activity focus remain unbroken throughout capture and transcription.

- **`BuildReleaseApk` (`Builds/Halcyonic-release.apk`)**: Moves `DevAgentSettings.asset` aside, builds without `BuildOptions.Development`, and deletes the APK if it contains any Meta development tool, `Operator` layer, `GlanceActivity` / panel preview / capture marker, boundary-hiding permission, unverified `stanley` glasses target, or permission outside `ChosenPermissions`, or if it omits `android.permission.RECORD_AUDIO`.

### Device verification boundaries and unbuilt scope

Automated `.NET` tests, JVM self-tests, and Unity Editor `RenderTexture` harnesses establish protocol fidelity, state-machine safety, layout geometry, Quest 3S angular containment, linear contrast, static font parity, zero-GC steady frames, and APK manifest hygiene (note also that the Meta XR Simulator fails to render on the development Mac, [meta-xr-platform.md](../validation/meta-xr-platform.md)). They do **not** substitute for physical Meta Quest 3 and Quest 3S sessions ([quest-3-device.md](../validation/quest-3-device.md), [quest-headset-in-the-loop.md](../validation/quest-headset-in-the-loop.md)):

- **Requires physical headset wear**: Long-session seated neck comfort and real-room passthrough glare at `0.46 m` plane distance and `Larger` text ([OPEN_QUESTIONS.md](../product/OPEN_QUESTIONS.md)); `SeatedHandRay` `20 degree` palm exclusion while typing on a physical desk; concave `ClippedCylinderSurface` poke feel; Quest 3 microphone gain/echo and speaker loudness over extended wear; Horizon OS window focus transitions alongside Virtual Display and Quest Browser, Android process reclamation/recreation across multi-view native-panel returns, and live Wi-Fi pairing and `PreviewRelayService` sessions on hardware; and real stereo GPU/CPU frame times (`DeviceMeasures`, `FrameTally`, `pnpm quest:session`).
- **Not built yet**: Browsing folders deeper than one level beneath host-approved project roots; attaching external agent sessions that Halora did not launch; shipping paired `PreviewRelay` or native-panel `PanelVoice` dictation in release APKs; wrapping stored pairing credentials under an Android Keystore hardware key; shipping offline-rendered panorama textures inside the APK so `WorldView` replaces Unity's stock skybox in Virtual Space; and typing arbitrary custom dollar amounts in `SpendingLimit` beyond the offered presets.
